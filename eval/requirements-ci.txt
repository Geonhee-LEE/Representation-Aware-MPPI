# Pinned environment for the eval/ measurement suite (D-032).
#
# WHY A PIN, AND WHY THIS IS NOT A NIT
#
# Five slow closed-loop tests -- the evidence for D-029 and D-030 -- pass under
# numpy 1.26.4 and FAIL under numpy 2.5.1 on the SAME box, same seeds, same
# code. The sandbox seeds every run with `np.random.default_rng(seed)`, whose
# stream is stable across numpy versions by policy, so this is not an RNG
# change: it is floating-point drift (SIMD / reduction-order differences)
# amplified by a chaotic closed-loop MPPI rollout until it crosses a threshold.
#
# Measured, not inferred (2026-08-03):
#   test_ab_temperature_protocol::test_protocol_moves_the_effect_size...
#   test_exposure_timing_band::...::test_reportable_scenes_land_inside...
#   test_hazard_exposure::test_refutation_reproduces_from_simulation
#   test_horizon_audit::...::test_the_prescribed_weight_moves_with_the_horizon
#   test_scale_match::...::test_the_prescribed_weight_achieves_the_requested_ratio
# 5 passed under 1.26.4 (149.95 s); all 5 failed under 2.5.1.
#
# The sharpest number: D-030's headline swing reads **2.0x** under 1.26.4 and
# **1.029x** under 2.5.1 -- i.e. under numpy 2 the horizon-dependence claim
# inverts, since the test's own message says a sub-1.2x swing would mean "a
# fixed-w_voo horizon column is honest after all".
#
# So the pin is a REPRODUCIBILITY CONTRACT, not a fix. It makes the measurement
# repeatable; it does NOT make it robust. Whether a result that flips on a numpy
# minor version should be carried as evidence at all is Q-054 -- open, and the
# pin deliberately does not pre-empt it.
#
# Residual, also measured: within numpy 2, this box and the GH runner agree to
# ~9 significant figures on one statistic (0.0362103793 vs 0.0362103796) but
# differ ~3% on another (0.03322 vs 0.03434). Pinning numpy removes the large
# term, not the small one. Do not read a green CI here as machine-independence.
#
# Before bumping any pin: re-run `pytest --slow -m slow eval/` and expect to
# re-derive the D-029 / D-030 constants, not merely to see green.
#
# Only numpy is pinned exactly -- it is the one that enters the arithmetic, and
# the one the divergence was measured on. pytest and pyyaml are bounded rather
# than frozen: the suite is known-good under pytest 7.4.4 (dev box) AND 9.1.1
# (runner, fast half green), so freezing either would assert a dependence that
# has not been observed.

numpy==1.26.4
